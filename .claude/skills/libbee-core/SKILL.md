# libbee — the portable C BeePack library

libbee is the C reference implementation of the BeePack format (skill
`beepack-format`). It replaces `sunriser8/src/bee.c`, becomes the engine behind
`p5-beepack` (XS via an Alien) and is the storage layer of CanLin. One code base, four
very different hosts — the constraints below exist because of the weakest of them.

## Consumers and what each one forbids

| Consumer | Host | Consequence for libbee |
|---|---|---|
| sunriser8 | STM32F1/F4, FatFS, **gcc 4.9**, no heap in the storage path | C99 only, no VLAs, no `malloc` in the core, I/O behind callbacks |
| CanLin | i686 **without SSE**, musl, static; Android/iOS via SDL | no SIMD, no glibc-only calls, mmap is a backend detail |
| p5-beepack | XS, any Linux/BSD | a plain C API with error returns, no `exit`, no `printf` |

## Shape

- **Core**: `bee.h` + `bee.c`, plus vendored `cmp.h`/`cmp.c` (the MsgPack codec
  sunriser8 already uses) and a CDB reader/writer. Nothing else is required to build.
- **Backends**: `bee_posix.c` (mmap-backed read, file-backed write) and `bee_fatfs.c`
  (FatFS `FIL`). A consumer links exactly one, or provides its own callback set.
- **No globals.** Every open file is a `bee_t`, every layered lookup a `bee_stack_t`
  the caller owns and initialises. Several stacks may be open at once — CanLin holds one
  per module. The firmware's `bee_obj` / `beepack_in` / shared `FIL` pattern is what
  this library retires.
- **No allocation in the core.** Buffers come from the caller; sizes are explicit
  parameters; a value larger than the buffer is an error, not a truncation. The POSIX
  backend may allocate (mmap) because its hosts have memory; the core must not know.
- **I/O is a positional reader** (`read(ctx, off, buf, len)`, `size`, `close`) carried
  in the context, plus a small `bee_fs_t` (open, write, unlink, list) for override
  directories and writers. Positional instead of read+seek keeps the reader stateless
  and lets the mmap backend implement `read` as `memcpy`. The core never includes
  `<stdio.h>`.
- **Errors are return codes**, one enum, with `bee_strerror()`. No logging inside the
  library; the caller decides what a missing key means.

## API surface (stable names)

Two levels, both in `bee.h` (full signatures: `docs/superpowers/specs/`):

- **Strict, error-returning** — what bindings use: `bee_seek(stack, key, klen)` then
  `bee_type`, `bee_get_bool` / `bee_get_u32` / `bee_get_i32` / `bee_get_bytes` /
  `bee_get_count`, `bee_next` to iterate a container, `bee_raw` for offset + length of
  the value bytes so large blobs stream without a copy on mmap hosts.
- **Firmware-style convenience** — zero value on any error, one call: `bee_has`,
  `bee_bool`, `bee_u32`, `bee_i32`, `bee_bytes`, `bee_array`, `bee_map`. These are the
  names `sunriser8/src/bee.c` exposes today, so the firmware port is a rename.
- Stack: `bee_stack_init(stack, fs)`, `bee_stack_push_file(stack, bee_t*)`,
  `bee_stack_push_dir(stack, path)` — most specific layer first.
- Writers: `bee_override_set*` / `bee_override_unset` / `bee_override_export` /
  `bee_override_import` (no allocation); `bee_make_begin` / `bee_make_add*` /
  `bee_make_finish` builds a `.bee` at a temp path the caller renames — host side, may
  allocate, never needed on the firmware.

## Strictness

The writer emits only the portable subset in `beepack-format`. The reader returns
`BEE_ETYPE` for float, 64-bit and ext values instead of coercing them. Override files
are accepted only when stored key length **and** bytes match the requested key.

## Testing

Tests are C programs under `t/`, run by `make test`, network-free. **Fixtures are
generated by the Perl `bee` tool from p5-beepack**, checked in under `t/fixtures/`
with the generating command in a comment or script next to them — the Perl writer is
the interoperability oracle, not our own writer. A change to the writer is verified by
reading our output back with Perl (`bee out.bee key`), not only with ourselves.

Build the i686 no-SSE configuration in CI as well as the host one:
`CFLAGS="-m32 -march=i686 -mno-sse -std=c99 -Wall -Wextra -Werror"`.
